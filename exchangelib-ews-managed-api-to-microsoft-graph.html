Exchange Online EWS · April 1, 2027

exchangelib and EWS Managed API stop working April 1, 2027

If your code reaches Exchange Online through exchangelib (Python) or the EWS Managed API (the .NET Microsoft.Exchange.WebServices package), it is an EWS client. Microsoft says EWS in Exchange Online is permanently disabled on April 1, 2027 (Exchange team blog), so these libraries stop working against Microsoft 365 mailboxes on that date. On-premises Exchange Server is not affected.

What changes

TodayAfter
Python exchangelib with Account, Credentials or OAuth2 to EWSMicrosoft Graph with the msgraph-sdk and msal packages, or plain HTTPS calls to graph.microsoft.com
.NET ExchangeService from Microsoft.Exchange.WebServicesGraphServiceClient from the Microsoft.Graph NuGet package
Basic or impersonation access to many mailboxesAn Entra ID app registration with Graph application permissions, limited to the mailboxes it needs
FindItems, account.inbox.all()GET /users/{id}/mailFolders/inbox/messages with $filter and $top
Message(...).send()POST /users/{id}/sendMail
CalendarItem create and queryPOST /users/{id}/events, GET /users/{id}/calendarView

The full operation-by-operation mapping is Microsoft's own (aka.ms/ews2graphMap). Not every EWS feature has a Graph equivalent: the mapping lists known gaps, including generic public-folder and Microsoft 365 group mailbox operations that it says won't be added, so check any code that touches them first.

What does not port line by line

  • Permissions. Graph asks for scopes such as Mail.ReadWrite or Calendars.ReadWrite. An app that impersonated a service account needs its access rethought, not renamed.
  • Paging and sync. EWS sync state and streaming notifications do not map to Graph one to one. Graph uses delta queries and change notifications.
  • Identifiers. Item IDs are different formats. If you stored EWS IDs, translate them with Graph's translateExchangeIds instead of assuming they match.

Do now

  1. Find every caller: the grep patterns or the free check list the files.
  2. Ask your admin whether EWS is already disabled in your tenant (disabling by default began in October 2026).
  3. Rebuild one flow end to end on Graph, then the rest.
