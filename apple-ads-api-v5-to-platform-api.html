Apple Ads API v5 to Platform API: what changes and what to edit

Apple's changelog says it plainly: "The Apple Ads Campaign Management API is deprecated and will be sunset on January 26, 2027. Use the Apple Ads Platform API instead." (Apple's changelog). Anything that calls https://api.searchads.apple.com/api/v5/ (or a leftover /api/v4/) has to move to https://api.ads.apple.com/v1/. Version 1.0 of the Platform API has been live since August 2026, so you can test against it today.

The five changes that touch your code

  1. Base URL. api.searchads.apple.com/api/v5/ becomes api.ads.apple.com/v1/.
  2. Context header. X-AP-Context: orgId=<orgId> becomes X-AP-Context: adAccountId=<adAccountId>. Ad accounts are new: list yours with GET /v1/acls or GET /v1/me.
  3. Nested resources become top-level. Keywords, ads and ad groups are no longer addressed through their parent's path. You query /v1/keywords/query with a filter such as adGroupId.
  4. Search renamed. find with a selector becomes query with filters, sorting and pagination (the page size limit for reports is 5000).
  5. Reports have a new body and a new response. See the reports page.

OAuth does not change. Same ES256 client-secret JWT, same token endpoint at appleid.apple.com, same scope searchadsorg. Updates are partial: a PUT replaces only the fields you send, and arrays are replaced whole.

Before and after

- BASE = "https://api.searchads.apple.com/api/v5"
- headers = {"Authorization": f"Bearer {token}", "X-AP-Context": f"orgId={ORG_ID}"}
- r = requests.post(f"{BASE}/campaigns/{cid}/adgroups/{agid}/targetingkeywords/find", json=selector, headers=headers)
+ BASE = "https://api.ads.apple.com/v1"
+ headers = {"Authorization": f"Bearer {token}", "X-AP-Context": f"adAccountId={AD_ACCOUNT_ID}"}
+ r = requests.post(f"{BASE}/keywords/query", json=query_with_adGroupId_filter, headers=headers)
