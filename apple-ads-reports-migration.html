Apple Ads reports: moving a reporting pipeline off v5

Reporting pipelines are where the Apple Ads migration hurts, because the report request and response both change. Reports are covered by Apple's Platform API documentation; this page is the short version.

v5 (going away)Platform API v1

Ad group reportPOST /reports/campaigns/{c}/adgroupsPOST /v1/reports/apps/adgroups/query with a campaignId filter

Request bodyStart/end dates, selector, groupBy, returnRowTotalstimeRange, filters, groupBy, pagination (max 5000)
Responsedata.reportingDataResponse.row[]result.rows[] with totalMetrics and granularMetrics

What to do in a pipeline

  1. Change the URL and the context header (adAccountId replaces orgId).
  2. Build the new request body: the old selector conditions become filters.
  3. Write one function that flattens result.rows[] into the same rows your tables already expect, so nothing downstream changes.
  4. Run old and new side by side for a week of data and compare totals before January 26.

The overall change list is on the main migration page.
