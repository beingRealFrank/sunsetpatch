Exchange Online EWS · April 1, 2027

Exchange Online EWS shuts off April 1, 2027: moving to Microsoft Graph

Microsoft's own blog post says EWS "will be disabled by default (EWSEnabled=False) in Exchange Online tenants that have not explicitly chosen to keep it enabled", and: "Starting with April 1, 2027, EWS will be fully and permanently disabled." It adds that there will be no exceptions past April 2027 (Microsoft Exchange blog; deprecation notice). This is about Exchange Online (Microsoft 365). Exchange Server on your own hardware is not affected.

Who is affected

Any code that reaches a Microsoft 365 mailbox, calendar or contact list over EWS: the EWS Managed API (Microsoft.Exchange.WebServices), exchangelib in Python, ews-java-api, /EWS/Exchange.asmx URLs, ews-javascript-api, RPA robots, CRM and ticketing mail connectors, and calendar sync tools. The replacement is Microsoft Graph. Microsoft publishes a mapping at aka.ms/ews2graphMap.

Typical mapping

EWS operationMicrosoft Graph
FindItem / GetItem on a mail folderGET /users/{id}/mailFolders/{folder}/messages, GET /users/{id}/messages/{id}
CreateItem (send a message)POST /users/{id}/sendMail
CreateItem / FindItem on calendarPOST /users/{id}/events, GET /users/{id}/calendarView
Contacts/users/{id}/contacts
AuthenticationOAuth 2.0 app registration in Entra ID with Graph permissions (for example Mail.ReadWrite), instead of EWS credentials or an EWS-scoped token

Check Microsoft's mapping for the exact operation you use. Two things to know before you plan: Graph has gaps (Microsoft says generic public-folder CRUD and Microsoft 365 group mailbox CRUD won't be added), and the access model is different, so an app that used impersonation needs its permissions redesigned. That is why this is a quote, not a flat price.

Do now

  1. Find every EWS caller (the free check looks for the hosts, libraries and scopes).
  2. Ask your Microsoft 365 admin whether EWS has already been switched off in your tenant. Disabled-by-default has been rolling out since October 2026.
  3. Register a Graph app, request the narrowest permissions, and rebuild one flow end to end before the rest.
